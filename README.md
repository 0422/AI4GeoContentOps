# AI4GeoContentOps

> 进度记录：2026-10-23。依据当前项目代码及本地使用过程中反馈的结果整理；“已接入”不代表对应外部服务已完成端到端验证。

AI4GeoContentOps 是在 Windows 本地运行的内容工作台。它把参考文章保存为样本，从同类样本建立可追溯的风格画像，再提炼可审核的写作策略，结合品牌事实生成文章初稿，由编辑人工修改。参考文章库已按“样本管理 → 发现与录入 → 风格画像”重组；新界面与接口尚待本机编译和浏览器验收。公众号候选发现已接入；RedFox 未返回正文的文章需手动补齐。

## 前端界面

前端使用 React、TypeScript、Vite 和原生 CSS。当前界面采用浅色中性主题，以细边框、清晰排版和少量状态色区分信息层级；颜色、字号、间距和圆角集中在 [设计 Token](frontend/src/design-tokens.css)，新视觉规则位于 [工作台样式](frontend/src/workspace-modern.css)。旧的 `workspace.css` 暂时保留供对照。本轮没有引入新的 UI 组件库，也没有改变后端接口或业务数据。

- 侧边栏已标明当前模块，右侧不再重复显示同名标题；生成页有最近任务时保留“查看当前稿件”入口。
- 参考文章库默认展示已入库文章。切换到“发现与录入”后可查询候选，点击“收录”或双击候选，在弹窗核对 RedFox 已返回的字段；接口未给正文时手动补齐。已入库文章的详情可维护来源、分类、权限、指标和分析状态。
- 风格画像使用独立的客观统计和可选模型语义分析；保存样本集、算法版本及来源关系。从画像创建的策略仍须在内容策略页人工审核发布。详细操作与指标口径见 [文章库说明](docs/article-library.md)。
- 生成页先展示匹配的策略结论，“查看写作规则”展开完整规则；新任务创建后定位到进度与稿件区域。人工修改仍需点击“保存修改”。
- 策略的参考来源按需展开；错误、权限确认、接口计费和保存状态等影响操作的信息继续显示。

后续开发页面可参考 [设计系统规范](docs/design-system.md)。当前只完成代码层面的调整，尚未完成桌面、笔记本和窄屏的浏览器视觉回归。

## 各页面的职责与操作顺序

1. **设置**：先检查类目、读者、形式、平台选项，并选择已配置密钥的默认模型。只有需要查询公众号候选时才配置 RedFox 密钥。
2. **参考文章库**：在“发现与录入”中按关键词或榜单查找候选，也可手动新增；核对原文、正文、分类和使用权限后保存。回到“样本管理”补齐作者、受众和发布时间，按需录入带时间与来源的指标快照。在“风格画像”选定样本范围并分析，检查统计与代表文章，再创建策略草稿。候选卡片和摘要都不等于已入库全文。
3. **内容策略**：可以直接勾选 1–6 篇合格样本提炼，也可以从文章库画像创建草稿。检查标题规律、关键词、语言、语气、结构、来源画像和避用规则，必要时编辑，再发布。调整已发布策略样本时创建新草稿；删除版本在“02 策略版本”中先选中再操作。
4. **品牌库**：保存品牌介绍及关键事实，为每条事实记录可核对的来源；审核并启用后才可用于新生成任务。
5. **内容生成**：填写具体创作主题、四类选项及可选补充提示词，选择匹配的已发布策略和已启用品牌，创建任务。页面会定位到任务进度；Worker 完成后查看文章，人工编辑后点击“保存修改”。任务创建时会保存策略与品牌资料快照，后续修改资料不追改旧任务。

策略只使用人工确认过的样本提炼。样本正文用于提炼写法，不会原样附到内容生成提示词中。即使文章可以在浏览器打开，程序也可能无法自动提取正文；此时以原文核对并手动录入为当前可用路径。

## Windows 本地启动

项目目录为 `E:\workspace\AI4GeoContentOps`。后端使用 PyCharm 已选的 Anaconda `learner` 环境；前端使用 Node.js 和 npm。在已能使用 `conda` 的 PowerShell 中运行以下命令；PyCharm 终端若已处于 `(learner)` 环境，可以跳过激活步骤。

首次安装后端依赖：

```powershell
conda activate learner
Set-Location E:\workspace\AI4GeoContentOps\backend
python -m pip install -r requirements.txt
```

将 `backend/.env.example` 复制为 `backend/.env`，只在后者填写实际密钥。例如使用 DeepSeek 生成时填写 `DEEPSEEK_API_KEY`；使用公众号 RedFox 查询时再填写 `REDFOX_API_KEY`。其他供应商可参考模板中的 `CUSTOM_LLM_*` 或 `LLM_PROVIDERS_JSON`。`.env` 已被 Git 忽略，不要把密钥写进前端代码。修改 `.env` 后重启 API 和 Worker。

<!-- 2026-10-24：本次修改原因：避免多次手动启动后留下旧 Uvicorn 工作进程，占用同一端口并持续提供旧接口。 -->
日常启动可直接双击项目根目录的 [`start-project.cmd`](start-project.cmd)，或在 PowerShell 执行 `./start-project.ps1`。脚本先识别并结束本项目的旧 API、Worker 和 Vite 进程，确认 8000、5173 端口空闲，再后台启动三个服务；若端口属于其他程序，会停止并说明原因。首次使用可运行 `./start-project.ps1 -DryRun` 只读预览将结束的进程。启动成功时会检查 API 已注册文章删除接口，并显示前端与 API 地址。日志保存在 `backend/data/service-logs/`；首次运行仍需先安装后端依赖及前端 `node_modules`。脚本不执行项目编译。

分别打开三个终端：

```powershell
# 终端 1：API
conda activate learner
Set-Location E:\workspace\AI4GeoContentOps\backend
python -m uvicorn app.main:app --reload
```

```powershell
# 终端 2：生成任务 Worker
conda activate learner
Set-Location E:\workspace\AI4GeoContentOps\backend
python -m app.worker
```

```powershell
# 终端 3：前端
Set-Location E:\workspace\AI4GeoContentOps\frontend
npm install
npm run dev
```

打开前端终端显示的本地地址。后端接口文档位于 `http://127.0.0.1:8000/docs`。`npm install` 只需在首次安装或依赖变化时执行；创建生成任务需要 API 和 Worker 同时运行。

## 数据保存与当前限制

- 任务、AI 生成结果、人工保存的当前修改稿、样本、样本元数据、指标快照、单篇特征、画像版本、策略、品牌和设置存于 `backend/data/tasks.db`。文章库扩展使用新关联表，已有样本表不需重建；正常重启后记录仍在，删除或重建数据库则会失去本地数据。`backend/data/` 已被 Git 忽略。
- 浏览器仅用 `localStorage` 记住最近一个任务编号，方便刷新后重新打开。换浏览器、清除浏览器数据或需要查找更早任务时，目前没有任务列表可用。编辑框中未点击“保存修改”的内容不会写入数据库。
- RedFox 候选查询会展示返回的阅读、点赞、在看、分享、评论等字段；某字段未返回就显示缺失，不推算“推荐”或“收藏”。不同榜单的时间、类目参数也不完全相同。
- 自动全文路径曾尝试 RedFox 详情、DeepSeek Fetch 和本机 Playwright 浏览器读取。发现页现在直接使用 RedFox 查询响应，不再在收录时二次取文；若响应只有摘要而没有正文，需打开原文手动补齐后保存。
- 当前没有其他平台的自动文章采集、自动事实核验、发布到平台、发布后数据回收或效果归因。多平台选项表示创作目标和手动样本分类，并不代表对应平台接口都已接入。
- 文章表现分组只比较同平台、类目、体裁、相近发布时间与账号规模，且发布后第 7–30 天有相同分母指标的文章；不足 10 篇可比文章时显示“暂不分组”。该分组不是未来流量预测。
