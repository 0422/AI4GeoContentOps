## 已实现交互

### 样本管理

- 初始宽度用于展示入库文章列表；选择文章后才展开右侧详情。
- 使用服务端分页，每页 20 篇；提供平台、内容类目、体裁筛选。
- 单击列表项加载详情，双击进入共用编辑窗口。
- 详情显示当前文章值、传播指标快照、权限范围、字段 provenance、来源请求参数、原始返回项目和原始正文。
- 编辑时以文章 `row_version` 做乐观锁；平台字段在编辑模式只读，因为后端 PATCH 契约不允许更改平台。

### 发现与录入

- 当前可用目标平台为微信公众号，支持关键词、10W+、原创爆款三种方式。
- 榜单方式显示 RedFox 榜单类目和日期范围；关键词方式显示关键词、排序和精确匹配。
- 查询结果按每页 10 条展示，可筛选全部、未收录、已收录；可全选当前页并批量收录。
- 点击已收录候选进入已入库文章详情；未收录候选可打开统一表单核对、补充并保存草稿或收录。
- 候选会话 ID 存在浏览器 `sessionStorage`，页面重新挂载时从目标库恢复，不会自动重新调用 RedFox。
- 手动录入复用相同文章表单和权限字段。
- 小红书、百家号、今日头条、多平台和知乎目前禁用并标明接入中；v2 后端尚未提供这些 Provider 的采集和收录契约。

### 数据校验

- UI 和服务端收录校验都要求标题、内部文章类目及至少 50 字正文。
- UI 要求明确勾选“允许保存到样本管理”；本地清洗、第三方模型及生成引用权限独立记录。
- 采集榜单类目保留为来源元数据，用户在收录表单中选择的文章类目保存为内部类目。
- 阅读量原始文本和下界语义保留；未提供的互动指标显示为“未提供”，真实零值显示为 0。

## 榜单候选反馈修正

维护者在 10W+ 查询结果中发现内部类目和发布时间未预填、候选列表将查询类目显示成文章类目，以及批量收录仍要求逐条核对的问题。本次相应修正：

- 候选保存请求类目与响应单项类目为两个字段；候选行明确区分“请求榜单类目”和“接口返回类目”，响应明确不一致时发出提示。
- 若请求类目名称与工作台文章类目选项完全一致，则在核对表单中预填内部类目，并随单篇/批量收录作为显式编辑值提交；正文相关性仍需人工核验，接口类目不被当作内容分类真值。
- 为历史候选会话补充回退：逐条候选没有请求类目时，从其 discovery session 的请求参数恢复并用于类目预填。
- 对历史候选的发布时间也补充回退：编辑器读取候选详情里保留的 `publishTime`/`publicTime` 原值提取日期；收录服务在标准字段仍为空时采用相同解析并写入 provenance。
- 无时区发布时间不再完全留空：保留源字符串，编辑值只采用原始日期部分，不推断时区或把时间改成 UTC。
- 移除收录表单中没有稳定来源的手工标签输入；旧字段代码保留注释供后续清洗/分析接入时参考。
- 点击收录动作本身确认本地存储；其他处理权限保持未知，未来在本地清洗、第三方模型分析、生成引用对应流程独立授权。批量收录统一提交字段齐全的文章，未齐文章明确列出待补充字段。

相关榜单契约测试已补充，但本次未运行测试或构建。RedFox SDK 文档确认接口支持提交类目和日期参数；服务端是否保证每条文章的语义相关度，仍需真实响应验证。

## 维护者验证

在已配置目标库并启动前后端后，请检查：

1. 打开参考文章库，初始只见文章列表；选择一条后详情面板出现。
2. 在发现与录入中分别执行关键词和榜单查询；离开页面再返回，确认候选从会话恢复且没有重新发起查询。
3. 保存候选补充后，确认草稿和 row version 刷新；补齐标题、内部类目、正文和保存权限后单篇收录。
4. 选中多条候选，测试不完整项仍可打开核对、完整项批量收录。
5. 对已收录候选验证进入样本详情；对文章双击或使用编辑按钮修改字段，重新打开后确认保存值和来源值并存。
6. 验证 10w+ 显示原始值及下界，缺失指标显示“未提供”，真实 0 显示 0。
7. 在浏览器开发者网络面板确认其他平台选项不可提交，查询按钮只在用户提交时调用 Provider。

Stage 2C 前端接入已形成可审查的纵向界面闭环。维护者完成本地类型/构建检查和上述手动验证后，可进入 Stage 3 清洗准备闭环；真实榜单响应 Fixture 仍是进一步核实字段完整性的门槛。
