# UI 审查与本轮改造

> 2026-10-23：依据当前前端源码和用户提供的 Modern Editorial SaaS 分析整理。此记录描述代码层面的改动，不代表已经完成浏览器视觉验收。

## 技术栈

前端为 React 19、TypeScript、Vite 8，使用原生 HTML 表单控件与手写 CSS。后端为 Python FastAPI。本轮不引入 Tailwind、shadcn/ui、图标库或动画库；避免为了视觉升级更换框架。当前会话提供的技能列表中没有 `frontend-design`、`ui-ux-pro-max` 或 `playwright` 技能，故本轮按设计规范直接实现，不声称调用了这些技能。

## 审查结果

| 发现 | 对使用的影响 | 本轮处理 |
|---|---|---|
| 左侧深色渐变、星形符号、英文眉题、页码和顶栏口号同时出现 | 装饰层级多于业务层级 | 统一为浅色导航与单一页面标题；保留原代码供对照。 |
| 多处使用 10–12px 字和绿色浅底标签 | 重要信息与辅助说明难区分 | 提升正文和控件字号，以中性色排版，状态色仅表达状态。 |
| 每个区域都是大圆角卡片，内部列表又使用小卡片 | 页面显得碎片化且占空间 | 列表改为行分隔；面板以细边框和适度留白组织。 |
| 样本页采集、长录入表单、样本列表同时常驻 | 浏览与录入相互抢占空间 | 默认浏览；手动录入或候选预填时再展开表单。 |
| 生成页长期展示完整策略规则，稿件位于长表单下方 | 创作重点被策略细节挤开 | 策略只展示匹配结果，细则按需展开；新任务自动定位到进度区，最近稿件可从页眉直达。 |
| 说明文字分散在页眉、横幅、字段下和卡片底部 | 常态信息重复，关键反馈被淹没 | 常见解释收进控件名称或按需展开；错误、权限、计费、保存状态仍显示。 |
| 品牌、策略和设置页使用不同密度的列表与表单 | 操作感觉不统一 | 统一按钮、输入框、状态、列表及标题的样式尺度。 |

## 文件与边界

本轮新增 `frontend/src/design-tokens.css`、`frontend/src/workspace-modern.css` 和设计文档；修改 `main.tsx`、生成、样本、策略、品牌、设置页面及模型设置组件。旧 `workspace.css` 保留，新视觉层在其后导入；这使本轮改动可审查，但后续应在确认视觉效果后整理旧声明。

未修改后端、API、数据库、路由、任务状态或品牌和策略的业务校验。样本库折叠表单只改变前端呈现：候选预填、全文失败后手动补录、权限确认与保存流程仍使用原有接口。
